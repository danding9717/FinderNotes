## 真实 Finder / Release 界面操作

以下由本轮 CUA 操作真实 Finder 服务和应用后，读取 macOS 辅助功能树核对；不是应用自测冒充 Finder，也没有截图。

测试根为 `/private/var/folders/j_/l8s7fghx6q73l51666cwkdw00000gn/T/findernotes-fn04-12pe5z3i`，runID `3e2b4f33-13bf-4b92-9cab-2ef9b53947a1`。只使用本轮新合成样本。MOV 经 ffprobe 确认为 16×16、1 秒 MPEG-4 视频。

| 操作 | 实际观察与边界 |
| --- | --- |
| PNG 冷启动 | 无 FinderNotes 进程时，在 Finder 选择 `normal.png` →“访达 → 服务 → FinderNotes 编辑笔记”。终端确认实际进程为 Release 路径、PID 67603；窗口显示正确路径和完整中文/emoji/空白正文，状态“笔记已加载”。 |
| 文本、查找、撤销/重做 | 粘贴中文、emoji、换行与空白；Command-F 出现原生查找栏，粘贴“中文”后上/下一个按钮启用；Command-Z 恢复原正文和加载状态，Command-Shift-Z 恢复草稿。尝试 CUA `typeText` 输入中文到查找栏未产生文字，改用 paste；这不构成真实 IME 通过。 |
| 重复调用 | 保留 PNG 草稿再次调用相同文件的服务，窗口正文不变；随后 Command-Z 仍可撤销之前粘贴。选区/marked text 细节另由组件测试覆盖，未冒充真实输入法验证。 |
| 关闭取消 | Command-W 出现“继续编辑 / 复制草稿 / 丢弃并关闭”；选择继续编辑后，原文件和草稿保持。 |
| 切换与复制 | 有草稿时请求 MOV，出现切换确认；选择复制草稿后仍在 PNG，Command-A/Command-V 回贴完整草稿一致。再次请求并明确丢弃后，读取 MOV 正文，窗口改为 `normal.mov`，同一运行进程。 |
| 多选 | Finder 全选 6 个样本后调用服务，显示“读取失败：请仅选择一个图片或视频文件”，原 MOV 草稿保留。 |
| 失败后保留 | 单选 `invalid.png` 显示 UTF-8 错误，单选 `unreadable.png` 显示打开文件 EACCES=13；均保持 MOV 路径和草稿。chmod 000 不是 TCC 拒绝实测。 |
| 空与缺失 | 明确丢弃后打开 `empty.png`，显示“已有空笔记”；打开 `missing.png`，显示“尚无笔记 · 可在此编辑草稿”。 |
| 丢弃关闭、空会话失败 | 在 missing 草稿上明确丢弃关闭，当前会话清空。随后打开 invalid，编辑器非 settable、复制按钮禁用且显示错误，未当作空笔记。工具观察会重新激活应用；窗口关闭的可见过渡仍需 Dan 观察。 |
