## 失败历史与证据边界

旧 Finder 原生注释路线的关键失败继续保留：未授权首次 AppleEvent `-1712`；在新合成 PNG/MOV 上同卷 CLI mv 后原生注释读回 0 字节，inode 与媒体哈希不变。它支持 D-006 的路线调整，不能推出所有 xattr 都会失败。旧路线误将 MOV 副本命名为 `.png` 的结果已排除；长文本 Finder 手工编辑和量化响应仍未测。详见 [E4]。

自定义路线的历史执行错误不隐去：FN-01 的 diskutil 参数错误与 unsigned 标签更正；FN-02 的 Python xattr API 不可用、Swift `hash` 命名冲突、`/private/var` 标准化误拒合法样本，以及 ScreenCaptureKit -3811/-3812。修正后的成功与早期失败分别保留。初始 FN-02 自测 `ok=false` 后有 28 项、最终 29 项记录；首次非受控的 `replace.png` 输入不计受控 `normal.png` 冷启动。详见 [E1][E2][E5][E7]。

所有通过均限原报告采样点。FN-02 独立核对的 16 个 UI 文件、14 个最终自测文件不包含已删除、不可读或符号链接对象；这些对象不能记为独立读取通过。FN-01 已验收但未勾选的 Finder 中间采样条目继续保留，不补勾。

## 建议支持范围与阶段门槛

建议继续的技术约定（**待 Dan 决定，不是本轮正式决策变更**）：

- 存储沿用 `com.findernotes.note.v1`；属性名表达版本，正文为原始 UTF-8，无 JSON 包装；仅一份正式笔记。区分缺失、零字节与读取失败，完整回读后才确认保存。16 KiB 是已测点，不是容量上限。
- 系统服务接收单个本地普通文件 URL；单文件、固定编辑对象、一个会话。多选、目录、符号/硬链接与替身按拒绝范围设计，未测的 Finder 菜单行为仍须验证。文件整理安排在保存并结束编辑后，不承诺编辑期间自动追踪移动或并发安全。

- 新笔记不显示或同步至 Finder 原生注释框，不自动迁移旧注释；保留其属性。Markdown 仅为独立导出快照，不是同步、第二份正式存储或 xattr 保存成功证明；M0 尚未实现导出。
