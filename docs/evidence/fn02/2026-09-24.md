## 服务与权限

实测菜单为 **访达 → 服务 → FinderNotes FN02 验证笔记**。把应用放到 `~/Applications` 并首次打开后自动出现，无需勾选新权限、重启 Finder 或重启系统。无选区时不显示。由服务菜单“服务设置…”可打开键盘快捷键的“服务快捷键”页；本次展开“文件和文件夹”与“文本”未找到 FN02 独立开关，未做关闭／重新启用／快捷键配置。设置差异保留为限制，不能声称已验证开关路径。

临时目录内 UI 读写过程中没有出现 Finder 自动化、完全磁盘访问或文件访问授权提示；因此本次不请求这些权限。此构建不是沙盒应用，没有安全作用域书签或持久化授权。不可访问路径通过真实 chmod 000 返回 EACCES 验证，但不是 TCC 弹窗中点击“拒绝”的测试。现有 Codex/Finder 自动化授权不被当作 FN02 权限证据；文件读写由日志中的 FN02 应用进程直接执行。

## 失败与修正

- 样本脚本首轮使用本机 Python 不提供的 `os.setxattr`，在新临时根生成部分样本后停止；改为系统 `/usr/bin/xattr`，重新生成全新根。
- 首次编译发生 NSObject `hash` 名称遮蔽；全局函数改为 `sha256` 后编译通过。
- 初次应用自测发现 Foundation `standardizedFileURL` 把 `/private/var` 变为 `/var`，隔离校验拒绝合法样本，没有写入。改为只接受已知 `/var` 系统别名并逐组件禁止符号链接。保留 [原始失败日志](initial-failed-selftest.jsonl)；随后 28 项、最终 29 项通过。
- ScreenCaptureKit -3811/-3812 多次中断读取界面；重新绑定应用、Dan 确认 Mac 解锁后继续。没有重启 Finder、重置 TCC 或关闭保护。
- 环境采集 `diskutil info -plist <任意目录>` 返回非零；按 `df` 的实际挂载点 `/System/Volumes/Data` 重取成功。不把 `/` 的只读系统快照当成测试卷。

## 未验证与剩余风险

- Finder 替身（alias）实际菜单行为、Finder 硬链接菜单调用、TCC 保护目录的允许／拒绝弹窗、sandbox／正式签名、首次安装 Gatekeeper、公证与分发，均未验证。
- 保存**中途**替换／删除的并发竞态、并发 xattr 修改、跨卷／NAS／云盘、大媒体、系统重启与服务缓存清理，均未验证。保持 fd 避免写入同名新对象，但最后检查与写入不是原子事务，详见源码 README。
- 草稿只在当前进程；没有自动保存、完整恢复或异常退出持久化。系统剪贴板是用户点击后的临时取回手段，不是恢复存储。
- 这轮独立检查保留哨兵和媒体内容，不重新声称已全面核对 Finder 原生注释及全部其他元数据；FN-01 既有未验证边界保留。
- 最终代码在首轮 UI 测试后只补强未绑定草稿保护、入口／退出前同步编辑框，并将自测与服务注册分开；最终 29 项自测、Finder PNG 冷启动／重复触发／保存已重跑。首轮完整 UI 错误矩阵未在最终构建全部重跑，Core 的文件读写保护逻辑未变。
