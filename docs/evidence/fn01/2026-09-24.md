## 文件生命周期测试进度

两类 `work/lifecycle.*` 先用 `write-verify ... mixed` 写入 80 字节注释，PNG 写／回读 247.72/241.15 ms，MOV 234.30/224.94 ms。Finder 中改名为 `renamed.png` / `renamed.mov` 后，`read <ROOT> work/renamed.* mixed` 均 **PASS**：PNG 263.53 ms、MOV 234.52 ms。PNG inode 仍为 `9140188`，MOV 为 `9140192`，设备号均为 `16777234`。

Finder 又把 MOV 同卷移入 `moved/`；`read <ROOT> moved/renamed.mov mixed` **PASS**：80 字节、281.72 ms、inode 仍为 `9140192`、媒体内容哈希仍等于 MOV 种子。Finder 复制 `copy.mov` 后，`read <ROOT> moved/copy.mov mixed` **PASS**：新 inode `9148913`，80 字节、389.58 ms、媒体哈希仍与 MOV 种子一致。

一次界面操作产生了 `moved/copy.png`，其内容 SHA-256 实际为 MOV 种子哈希 `706c5ef9bcd096289add49618a86e9a5d09795b029732d19140bbc025c4ec87d`；虽然注释读到 80 字节，探针因媒体内容不匹配而退出 1，**不能**计作 PNG 复制成功。为保留这次失败证据，将其在临时目录内改名为 `moved/misnamed-mov.mov`，没有删除。随后由于电脑控制接口持续返回 ScreenCaptureKit `-3812`，用命令行 `mv` 把 `work/renamed.png` 移至 `moved/renamed.png`，并用 `cp -p` 从该原件生成正确的 `moved/copy.png`。因此 **PNG 的移动／复制不是 Finder 界面操作**，不能据此声称 Finder UI 的 PNG 生命周期已验证。

这一命令行移动暴露了关键失败：`moved/renamed.png` 仍是设备号 `16777234`、inode `9140188`，媒体哈希仍等于种子，但 `read ... mixed` 报实际注释 **0 字节**、预期 80 字节，退出码 1；`copy.png` 是新 inode `9149770`、152 字节真实 PNG，仍读到原来的 80 字节注释，媒体哈希正确。为排除操作混淆，又各新建一个 `mv-probe.png` 和 `mv-probe.mov` 合成副本：分别先运行 `write-verify ... mixed` 通过（PNG 写／回读 275.60/246.04 ms，MOV 261.93/244.98 ms），再用同卷命令行 `mv work/mv-probe.* moved/mv-probe.*`，两者立即 `read ... mixed` 都 **FAIL**：实际 0 字节、预期 80 字节，设备号与 inode 各自保持不变，媒体哈希保持不变。PNG 读取 238.96 ms、MOV 238.77 ms。这证明在本机环境和此操作路径下，Finder 注释并不可靠地跟随普通文件系统移动；不能把失败解释为媒体数据丢失，也不能把返回空文本当作无注释。

为继续测试副本隔离，单独将 `moved/renamed.png` 的 80 字节注释重新写入并回读通过；**重写不抹除前述移动丢失的事实**。再仅把 `moved/copy.png`、`moved/copy.mov` 改写为 2,000 个“航”（各 6,000 UTF-8 字节），逐字节回读通过。最后分别读取原件 PNG/MOV，仍是 80 字节 `mixed`，副本 PNG/MOV 则是 6,000 字节 `cjk2000`，四个媒体哈希均与各自种子一致；原件／副本 inode 互异。这个隔离测试证明两个当前副本可独立编辑，其中 MOV 是 Finder UI 复制，PNG 是命令行 `cp -p` 复制。

## 结论与未验证项

**通过：** 本机授权条件下，两类合成媒体的 Finder 已有注释、程序写入、Finder 界面手工修改均可双向读回；80 字节、2,000 中文字符、16 KiB 样本逐字节一致；Finder UI 改名两类媒体及移动／复制 MOV 后注释仍关联；媒体数据哈希未变化；副本编辑彼此独立。

**失败：** 未授权时首个 AppleEvent 读取超时 `-1712`；同卷命令行 `mv` 对 PNG/MOV 均使 Finder 注释读回为空，已在新副本复现。误将 MOV 复制品命名为 `.png` 的一次操作由媒体哈希检查发现并排除。这些都没有伪装成通过项。

**未验证：** 由于电脑控制接口持续出现 ScreenCaptureKit `-3811/-3812`，PNG 的 Finder UI 同卷移动／复制及长文本 Finder 界面直接修改未完成；没有长文本界面响应的可靠量化结论。也未测外置／网络／iCloud 卷、跨卷移动、系统重启、正式应用签名／沙盒及拒绝授权。16 KiB 是测试点，不是容量上限。

**风险判断：** Finder 原生注释若作为唯一笔记存储，普通文件系统移动使正文读回为空是阻断性风险。Finder UI 移动 MOV 通过，并不能替代其他移动方式的可靠性。M0 验证代码不实现产品修复，也不在本轮擅自修改正式设计决策；需要 Dan 审阅这项风险并决定是否允许后续架构依赖 Finder 注释。临时目录保留供复核，不自动清理。
