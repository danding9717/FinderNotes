# M0 隔离验证方案

本文件给 FN-01 和 FN-02 提供可复现的测试方法；实际结果写入对应任务与 Git 中的证据记录。本方案本身不是通过证据。必须先取得 FN-00 对 M0 的明确批准，并验证完整 Xcode 工具链，才开始写入或 Finder 权限测试。

## 环境与样本

每次运行记录 macOS 版本与构建号、芯片、Xcode 与 SDK、应用标识、签名／沙盒配置、授权结果、测试卷及文件系统。以当前机器本地 APFS 上新建的独立临时目录为测试根；只使用自行生成的图片、短视频和它们的副本。不指向 Orbit 仓库、服务、数据库或真实素材。

文本样本分别覆盖：中文与 emoji、多段落、首尾空白、引号、反斜杠、约 2,000 个中文字符和 16 KiB UTF-8 数据。样本实际 UTF-8 字节数与 SHA-256 应写入证据；样本长度不是系统上限。

## FN-01：注释与文件关联

1. 读取当前 Finder 脚本字典，确定实际支持的读写路径；读取测试文件已有注释。读取失败单独报错，不当作空字符串。
2. 对每个文本样本进行程序写入和完整回读，并由 Finder“显示简介”人工核对；再由 Finder 修改，验证程序读回。记录原文与回读是否逐字相同、耗时和响应情况。
3. 关闭验证程序后，在 Finder 中改名、同卷移动和复制，再从新位置核对关联；编辑副本后确认原件注释不变。
4. 写入前后计算测试媒体**内容**的 SHA-256；记录元数据可能变化的事实。不声明所有元数据未变化。
5. 分别记录成功、失败和未验证场景。若正文截断、基本关联或关键读写失败，保留证据并停止扩大实现。

## FN-02：服务入口与权限

使用最小本机应用验证冷启动、热启动、重复触发、单文件 URL、多选、目录和链接。分别由 Dan 在真实系统提示中验证允许与拒绝自动化授权；测试只读文件、目标消失和同名替换。记录服务启用方法、菜单实际位置、错误提示、延迟和失败后草稿能否保留、复制或导出。

M0 的失败保留草稿只要求当前运行期间仍可取回文本；异常退出后的持久化恢复属于 M2。终端已有授权、编译成功和 mock 结果不能代替应用身份下的 Finder 实测。

## 证据记录格式

每个场景记录：日期｜对应 FN 任务｜环境与权限｜测试文件身份与样本哈希｜实际命令或人工步骤｜预期｜实际｜通过／失败／未验证｜原始日志或截图路径｜风险与下一步。日志只保留合成数据，不含令牌或无关私人文件；提交前检查路径和内容。Notion 任务卡写结果摘要、提交或 PR 链接，Dan 验收后才更新为 `Done`。
