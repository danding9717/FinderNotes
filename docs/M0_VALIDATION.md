# M0 隔离验证方案

本文件给 FN-01 和 FN-02 提供可复现的测试方法；实际结果写入对应任务与 Git 中的证据记录。本方案本身不是通过证据。当前存储路线以 Notion“设计与决策”的 D-006 为准：直接读写自定义 xattr，保留旧 Finder 原生注释实验作为历史证据。每项实现均须获得授权并满足任务卡依赖，不能因修订本方案而自动启动后续任务。

## 环境与样本

每次运行记录 macOS 版本与构建号、芯片、Xcode 与 SDK、探针或应用标识、签名／沙盒配置、运行身份、授权结果、测试卷及文件系统。命令行探针与正式应用的权限环境分别记录，不适用项注明原因。以当前机器本地 APFS 上新建的独立临时目录为测试根；只使用自行生成的图片、短视频和它们的副本。不指向 Orbit 仓库、服务、数据库或真实素材。

文本样本分别覆盖：中文与 emoji、多段落、首尾空白、引号、反斜杠、约 2,000 个中文字符和 16 KiB UTF-8 数据。样本实际 UTF-8 字节数与 SHA-256 应写入证据；样本长度不是系统上限。

## FN-01：自定义 xattr 与文件关联

1. 使用唯一自有属性 `com.findernotes.note.v1` 保存原始 UTF-8 正文；不使用 JSON 包装，不自动 trim、规范化换行或替换字符。新属性不存在、已有零字节空正文、读取错误和无效 UTF-8 分别记录，不能把错误转成空笔记。主动清空的行为必须明确，并验证其与属性不存在的区别。
2. 对每个文本样本进行探针写入与逐字节回读，比较实际字节数和 SHA-256，记录耗时；结束写入进程后，由新进程重新读取。使用系统 `xattr` 工具独立读取十六进制属性值并还原字节，与样本比较，避免仅用同一实现自证正确。需要验证外部修改时，也以独立工具写入合成正文后让探针读取。
3. 关闭写入进程后，分别用 Finder 和命令行对合成 PNG、MOV 执行改名、同卷移动和复制，再从新位置读取自定义笔记。各条路径单独记录文件身份与结果，不用命令行通过替代 Finder 实测。特别复验旧方案失败的同卷 `mv`；复制后编辑副本，并核对原件正文未变、文件身份相互独立。
4. 写入前后比较测试媒体**内容**的 SHA-256、Finder 原生注释属性及其他已有扩展属性。只修改自有属性，保留无关属性的原始字节；不直接修改 `.DS_Store`，不以 Spotlight 缓存为保存结果。文件操作可能产生的系统元数据变化单独说明，不宣称文件所有元数据均不变化。
5. 在隔离副本上验证只读、目标消失、同名替换、身份无法确认、错误类型及写入失败后的原值保留。只读或权限测试必须记录真实返回结果，不能仅凭设置了权限位就认定操作应失败。测试后只恢复本次主动修改的测试副本状态，不自动扩大系统权限。
6. 分别记录成功、失败和未验证场景。正文截断、基本关联或关键读写失败时保留证据，停止扩大实现。新笔记不显示在 Finder“显示简介”的原生注释框，因此不再以原生注释框的双向编辑作为新路线验收；保留已有原生注释仍属于兼容性检查。

探针入口为 `validation/fn01/build-xattr.sh` 与 `validation/fn01/run-xattr.py`，具体命令与 Finder 步骤见该目录的 README。跨卷复制、同步盘、NAS、云端占位文件、压缩或聊天软件转发不作默认保证；没有实际执行的场景明确标为未验证。FN-01 提交验证结果不代表已经批准 M1。

## FN-02：服务入口与权限

FN-02 尚未启动；须在该任务获授权后，使用最小本机应用验证冷启动、热启动、重复触发、单文件 URL、多选、目录和链接。按实际入口与文件访问方式测试授权、拒绝或不可访问、只读、目标消失和同名替换；记录是否出现系统授权提示及真实结果。直接读写自定义 xattr 不默认要求控制 Finder；只有实际入口确实使用自动化时，才由 Dan 在系统提示中决定对应授权。

记录服务启用方法、菜单实际位置、错误提示、延迟和失败后草稿能否保留、复制或导出。不默认索要完全磁盘访问，不自动改权限、重置授权或关闭安全功能。

M0 的失败保留草稿只要求当前运行期间仍可取回文本；异常退出后的持久化恢复属于 M2。终端已有授权、编译成功和 mock 结果不能代替应用身份下的 Finder 实测。

## 证据记录格式

每个场景记录：日期｜对应 FN 任务｜环境与权限｜测试文件身份与样本哈希｜实际命令或人工步骤｜预期｜实际｜通过／失败／未验证｜原始日志或截图路径｜风险与下一步。日志只保留合成数据，不含令牌或无关私人文件；提交前检查路径和内容。Notion 任务卡写结果摘要、提交或 PR 链接，Dan 验收后才更新为 `Done`。
