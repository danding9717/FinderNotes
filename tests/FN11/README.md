# FN-11 verification

Run from the repository with `scripts/verify_fn11.sh`. It builds into `.build/FN11`, compiles the component executable with the same production sources and resolved Markdown dependency, and runs it without installing or launching FinderNotes. `FINDERNOTES_DEVELOPER_DIR` selects full Xcode. It uses Debug by default; `FINDERNOTES_CONFIGURATION=Release` selects Release. `FINDERNOTES_FN11_SKIP_BUILD=1` reuses an already successful build of that configuration.

The harness checks supported Markdown constructs, nested structures, Unicode source ranges, incomplete syntax and conservative retention of unsupported syntax. It also exercises programmatic AppKit presentation and the existing save, export and recovery paths with raw UTF-8 equality. Every storage write uses its own `FinderNotes-FN11-<UUID>` temporary directory and an embedded PNG fixture. The directory and isolated UserDefaults suite are removed on completion. Build and verification output stays below `.build`.

A hidden production `EditorWindowController` exercises the native text-change delegate, autosave callback, manual save and newer edits arriving during an older save. Raw full-draft and selected-source copies use a unique named pasteboard, preserving the user's general pasteboard.

List Return checks exercise the production `insertNewline` override: ordered and unordered prefixes, the compact `1.text` form, indentation/separator retention, splitting and replacing item text, empty-item exit, one native character edit and one undo/redo step. Task Return creates an unchecked next task and empty tasks exit. Code fences and disabled Markdown use native Return. Simulated marked Return is compared with native behavior so candidate confirmation cannot inject a list prefix. The production editor integration confirms that continuation reaches draft revision and autosave as raw source, using a temporary PNG and xattr.

Task checkbox checks use the production layout's actual checkbox rectangle and a native `mouseDown` event. They verify one status-character change, original-selection retention, immediate collapsed presentation, undo/redo, uppercase-X source, disabled/marked/current-paragraph protection, and cached hit positions after an earlier UTF-16 emoji/combining edit while parsing is held. A hidden production editor verifies that checkbox clicks advance the draft once and autosave the exact raw source without changing PNG bytes.

Optional real UI review uses a separate executable: `FINDERNOTES_FN11_BUILD_TASK_UI=1` with `scripts/verify_fn11.sh` compiles `.build/FN11Verification/fn11-task-ui` without executing it. This selects a synchronous AppKit entry point with `FN11_TASK_REVIEW_UI`; the normal verification keeps its async entry point. A reviewer can explicitly launch `fn11-task-ui --task-ui /absolute/path/task-ui-context.json`, or package it in a test bundle whose `FN11TaskReviewContextPath` Info.plist key supplies the output path. It presents a window titled `FN-11 task UI`, uses a unique temporary PNG/xattr and preference suite, and installs a small native Edit menu for keyboard undo/redo. The JSON records fixture paths, original source, preferences and checkbox geometry. This mode preserves its fixtures for review evidence and must be explicitly launched and cleaned up by the reviewer; the normal verification command does not launch it.

The input-stability suite holds real parser results behind an asynchronous gate. It inspects distant paragraph fonts, other attributes, hidden delimiters and decorations immediately after each native edit, while parsing is blocked, and after the result applies. Storage notifications and the controller's changed-paragraph ranges check that distant attributes are not rewritten. Cases include UTF-16 emoji insert/delete, newline merging, multiple-paragraph insertion, undo/redo, selection changes during a pending parse, and simulated marked-text growth, shrinkage, unchanged-byte commit and cancellation. A fence change and a 180-item list change compare the settled display with a complete fresh parse. These checks demonstrate deterministic intermediate states; they do not measure a rendering latency or real IME performance threshold.

Pure edit/cache checks cover verified AppKit edit metadata and conservative fallback, surrogate boundaries, CRLF, byte-distinct NFC/NFD strings, range rebasing, offset-independent paragraph presentation, heading/nested traits while expanded, and invalidating an old EOF paragraph after appending text. Native first-input checks cover the middle and end of a heading and the following blank paragraph; layout toggles also preserve the scroll origin. The executable reports the total assertion count for the exact run.

These are component checks. They do not establish real input-method, Finder service, TCC, installed-build or long-session behavior. In particular, `setMarkedText` simulates the AppKit composition state and does not exercise a Chinese IME.

The harness also caches the actual production `NSTextView` display as `.build/FN11Verification/layout.png` and verifies that hidden syntax generates null glyphs with zero horizontal layout advance. This bitmap is programmatic AppKit component rendering, not a screenshot of Finder service use.

`rule-eof-1.png` and `rule-eof-2.png` exercise a fully hidden final rule with and without preceding text; pixel checks place the line in its native final layout fragment. The standalone rule case configures the production glyph manager directly because the normal controller keeps the caret's sole paragraph expanded.

Manual acceptance should use a disposable image or video copy and cover:

- Move the caret into and out of each supported construct; syntax reappears for editing and returns to presentation after leaving the paragraph.
- Type Chinese with a real IME, switch candidates, commit and cancel. Check text, caret and candidate placement while formatted text is visible.
- Select across multiple paragraphs, edit and undo/redo; check selection and scroll position. Copy and paste into a plain-text editor and verify raw Markdown markers.
- Turn presentation off and on, reopen the app and check the preference persists. Check unsupported tables, HTML, images and formulas remain readable as source; task checkboxes still reveal their raw prefix in the current paragraph.
- Save and reopen a note, export it, and recover an unsaved draft. Compare raw source, not only visual appearance.
- Try representative long notes and continuous edits; observe delayed formatting and current-document correctness without claiming a performance threshold from this harness.
