# FN-08 本机试用与验收

本目录提供 FN-08 的新合成副本和独立核对方法。以下是操作步骤与预期，未勾选清单不代表已执行；本轮实测结果保存在 [FN-08 证据目录](../../docs/evidence/fn08/)。安装与日常使用见 [本地试用手册](../../docs/LOCAL_TRIAL.md)。不读取或操作 Orbit、真实媒体或历史验收样本。

## 身份与准备

```sh
FINDERNOTES_DERIVED_DATA="$PWD/.build/DerivedData-build11" \
  FINDERNOTES_BUILD_PROFILE=local-trial ./scripts/build_app.sh
python3 -B scripts/install_local_trial.py
python3 -B validation/fn08/prepare.py
```

当前图标更新的本地试用 Release 为 `com.findernotes.FinderNotes.LocalTrial`、`0.1.0 (11)`；服务为“用 FinderNotes 编辑笔记”。测试宿主 `com.findernotes.FinderNotes.FN08Tests` 不声明服务。安装默认源为 `.build/DerivedData-build11/Build/Products/Release/FinderNotes.app`，目标为 `~/Applications/FinderNotes.app`，已存在即拒绝覆盖。原 build 8／9／10 安装件及其各自 DerivedData 保留；这些副本共用 LocalTrial 服务及恢复目录，不迁移、清理或同时运行。应用是本机 ad hoc、非沙盒、未公证；deployment target 26.0 不代表该系统已经实测。

以下完整测试命令供后续需要时复现，本次图标更新未重跑既有 140 项测试；历史数量与 Finder/UI 结果仍属于 build 8。显式新目录可避免替换旧测试宿主和构建副本，xcresult 仍使用独立时间戳路径：

```sh
FINDERNOTES_DERIVED_DATA="$PWD/.build/DerivedData-build11" \
  FINDERNOTES_BUILD_PROFILE=local-trial ./scripts/test_app.sh
```

`prepare.py` 每次创建全新的 `findernotes-fn08-…` 根。将其输出的完整路径写入本轮报告，不复用 FN07 根，不清理既有应用、恢复目录或原始证据。样本使用程序生成的图片、视频及音轨；生成器需要本机已有的 `ffmpeg`，这是合成样本依赖，不是应用运行依赖，脚本不自动安装它。`before.json` 保存身份、权限、媒体 SHA-256 与原始 xattr，`.fn08-owned.json` 标识本轮独立根。只对清单内的合成文件进行变更。

```sh
fixture_root="/absolute/path/to/findernotes-fn08-NEW"
python3 -B validation/fn08/verify.py "$fixture_root"
python3 -B validation/fn08/verify.py "$fixture_root" --file empty.png --expect-note empty.png=
python3 -B validation/fn08/verify.py "$fixture_root" --file missing.png --expect-note missing.png=missing
```

`--file` 和 `--expect-note NAME=HEX` 均可重复；HEX 是完整 UTF-8 原始字节的十六进制，`NAME=` 为空属性，`NAME=missing` 为缺失。保存原始输出时每次选一个新文件名，保留错误和非零退出。独立核对必须比较媒体、身份、权限、Finder 原生注释与全部无关 xattr；不能只比较自有正文或只看媒体哈希。没有指定正文预期时与初始状态比较，已编辑文件须使用精确正文预期，不能把正常笔记变更误报成回归。

## 分开记录三类证据

| 层次 | 记录内容 | 不能替代的结论 |
| --- | --- | --- |
| 确定性／AppKit 测试 | 命令、实际源码、完整日志、xcresult、用例数量及失败／条件跳过 | Finder 服务派发、真实输入法候选、实际声音、TCC |
| 真实文件集成 | 新合成根、前后身份、媒体和 xattr、预期 mutation、导出与恢复文件 | 实际应用窗口交互和用户接受 |
| Finder／UI 与人工观察 | 安装件实际进程路径、PID、Finder 选择与服务、窗口状态、操作顺序、AX／有效截图；Dan 的现场观察 | 未执行的其他身份、系统版本、存储位置或传输工具 |

本轮原始日志、有效截图、AX、JSON、SHA-256 和合成样本路径应集中索引；只粘贴正文不算中文输入法证据，程序化 marked text 不算真实候选，0444 权限失败不算 TCC 拒绝。历史证据单独链接，不覆盖旧日志或给旧清单补勾。

当前构建 11 统一软件名为 FinderNotes，版本只在关于中显示；旧图标和功能证据按各自构建保留。本轮名称证据见 `docs/evidence/fn08/name-build11/README.md`。

- [ ] **真实中文输入：** 使用实际中文输入法，保留候选组合超过自动保存延迟，观察未提交拼音是否被保存；提交候选后再次独立读取。撤销／重做、选区、光标与长文滚动分别观察。粘贴、英文键入和程序化组合态不可代替。
- [ ] **Markdown 导出：** 导出当前草稿到新路径，比较 UTF-8 字节；同名目标必须保留原件，取消和失败须保留草稿。导出不改变 xattr 保存事实，重复编辑不自动同步已导出文件。

## 失败与草稿保护清单

- [ ] **多选和无效对象：** Finder 多选调用应明确拒绝，不覆盖当前草稿或错用第一份文件；目录、符号链接、硬链接和替身按当前拒绝范围分别记录证据层次。
- [ ] **外部正文修改：** 打开 `conflict.png` 后，仅在本轮副本外部改自有 xattr，再编辑／保存。应暂停自动保存并保留两方。“继续编辑”不丢稿；载入外部前先导出本地；覆盖前先导出外部且再次明确确认。导出取消／失败不能改变当前草稿；完成导出之后仍需重新核对外部版本。
- [ ] **属性删除与空字节：** 使用独立副本分别删除自有属性、设为空字节、保持缺失，确认三者与读取失败有区别。删除不是空正文；不得静默覆盖外部变化。故意修改的属性在 mutation 中单独记录，不混作应用修改。
- [ ] **同名替换与消失：** 把原合成对象保存在本轮 archive 中，再建立同名、同媒体／正文的独立副本；应拒绝写回新身份。原目标移走／消失也不得误写；原稿可复制／导出。不操作真实文件。
- [ ] **权限拒绝：** 本轮 `readonly.png` 的 0444 导致保存失败，应暂停并保护草稿，不能显示已保存。只在这个副本恢复写权限后手动保存，核对正常恢复。此项是 Unix 文件权限，不填作 TCC 通过。
- [ ] **真实 TCC：** 只有经 Dan 自行操作必要系统提示，并记录应用身份、位置、允许／拒绝与失败保稿，才可记录相应结果。没有真实受保护位置实验时保持未验证，不默认要求完全磁盘访问、辅助功能或控制 Finder。
- [ ] **预览失败：** 损坏合成图片／视频的系统占位不应阻止编辑、复制、保存和导出；URL 设置成功不代表预览渲染成功。
- [ ] **关闭／切换／退出：** 有草稿或保存失败时默认返回编辑，复制仍留在当前会话；仅明确丢弃离开。取消对话框后正文、撤销、选区保留；保存进行中不伪装取消或提前关闭。

外部变更工具只可接受本轮 marker 和原始清单内的合成对象。若不使用已验证的受限工具，先保留完整前后快照与原件再操作；不要把 FN07 的 mutation 工具直接指向 FN08 根，也不把顺序测试工具称为并发安全写入 API。

## 传输、卸载与交付核对

`python3 -B validation/fn08/transfer_probe.py` 会新建独立的 `findernotes-fn08-transfer-…` 根，只对新合成 PNG 观察本机同卷 `cp -p`、显式保留属性的 `ditto`、系统 `ditto` ZIP 往返和 Python 标准 ZIP 往返。报告保存在该根的 `transfer.json` 并输出原始命令与属性比较；`completed` 表示实验执行完成，不能将某条 `noteMatches=false` 改写为保留成功。没有访问实际备份、云盘、NAS、外置卷或通信接收端。

- [ ] 对实际执行的复制／备份／压缩解压逐个记录工具、版本、参数、源与目的位置、媒体 SHA-256、完整 xattr 字节和独立读取结果。跨卷、云盘、NAS、转发等未执行组合保持未验证；普通复制不是备份恢复证据。
- [ ] 核对卸载说明只作用于本次安装 app；媒体上的笔记、恢复目录、导出 Markdown 与历史验收资源保留。任何删除自有 xattr 或恢复记录都另行标明破坏性，不作为默认卸载。
